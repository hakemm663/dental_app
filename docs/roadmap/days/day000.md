## Baseline: Dental App (Lab Project)

The existing dental app is the working project for all roadmap implementation
work, replacing the "build a vulnerable lab app" step with a real, evolving
codebase to harden.

- `flutter pub get` — succeeds. 52 transitive packages have newer versions
  available but are pinned by current constraints; no action taken (out of
  scope for Day 0, and dependency bumps require justification per CLAUDE.md §5).
- `flutter analyze` — **18 issues, all `info` severity**, zero warnings/errors.
  All findings are pre-existing in app feature code, not roadmap code:
  - `use_null_aware_elements` — `lib/core/networking/api_service.dart`,
    `lib/features/home/presentation/cubit/profile_cubit.dart`
  - `unnecessary_underscores` — `lib/features/inbox/presentation/widgets/message_bubble.dart`

**Decision:** These `info`-level lints are recorded as the **baseline** and are
left untouched. CLAUDE.md §4 (Change Discipline) forbids refactoring unrelated
code; the Quality Gate "zero `flutter analyze` issues" applies to *code each
roadmap day produces*, and Day 0 produces none. Future days that touch these
files should clean them up opportunistically.

---

## Key Decisions

1. **Lab app = production app.** The dental app itself is the security lab. Each
   roadmap day hardens real features rather than a throwaway vulnerable app.
2. **HTTPS over SSH for git.** No SSH key setup required; HTTPS remote is
   functional. SSH key registration deferred as optional.
3. **Analyze baseline frozen.** 18 pre-existing `info` lints documented and
   left as-is to respect change discipline.
4. **Emulator note for Day 1.** Android emulator must be launched with
   `-writable-system` for Frida server installation — flagged ahead.
