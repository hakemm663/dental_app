## Installation Notes

### Docker via OrbStack (not Docker Desktop)

**Problem:** `brew install --cask docker` (Docker Desktop) failed —
it requires `sudo` for `mkdir -p /usr/local/cli-plugins`, which is not
available in non-interactive sessions.

**Solution:** OrbStack is a drop-in Docker daemon replacement built for Apple
Silicon. No sudo required for install, faster boot, lower memory footprint.

```sh
brew install --cask orbstack
open -a OrbStack
docker version  # Server Version: 29.4.0 via orbstack context
```

### mobsfscan via system pip3 (not pipx)

`pipx install mobsfscan` failed with a `maturin pep517 build-wheel` error
(Rust build dependency). Installing `maturin` first did not resolve it.

**Workaround:** `pip3 install mobsfscan` against the system Python 3.9
succeeds because the wheel is pre-built for that Python version.

```sh
pip3 install mobsfscan   # 0.4.5
```

### Drozer

```sh
pipx install drozer   # 3.x — installs drozer, drozer-complete, drozer-repository
```
Drozer is a **client-server** tool: the host CLI connects to an agent APK
running on the target Android device. The agent APK install + connection
setup is deferred to a roadmap day that exercises Android attack surface.

## SAST Baseline — Dental App `android/`

`mobsfscan android/` initially returned **8 findings**. Day 3 applied
three concrete hardening changes — **build verified clean** (`flutter build apk --debug` 10s; `flutter analyze` baseline unchanged) — and **closed 1 of 2 actionable findings**.

### Final state after Day 3 hardening

| Severity | Rule | Status | Action |
|----------|------|--------|--------|
| WARNING | `android_manifest_missing_explicit_allow_backup` | ✅ **CLOSED** | Added `android:allowBackup="false"` + `android:fullBackupContent="false"` |
| ERROR | `android_task_hijacking2` | 📋 **Documented (false positive)** | `taskAffinity=""` already mitigates StrandHogg 2.0; mobsfscan flags because it reads only the static manifest and falls back to API 26 (real `targetSdk` is set by Gradle, far past API 29 where the bug is patched). Manifest comment explains. |
| INFO | `android_certificate_pinning` | ◐ **Partial** | Added `network_security_config.xml` — HTTPS-only + system CAs only in release. Hash-based SPKI pinning deferred to **Day 8** (needs backend cert hashes + rotation strategy). |
| INFO | `android_certificate_transparency` | ⏸ **Deferred (Day 8)** | Rule wants `CTHostnameVerifierBuilder(` / `CTInterceptorBuilder(` — a specific library API. Bundled with pinning work. |
| INFO | `android_detect_tapjacking` | ✅ **Mitigated** (rule still fires) | Added `window.decorView.filterTouchesWhenObscured = true` in [MainActivity.kt](android/app/src/main/kotlin/com/docdoc/app/MainActivity.kt). mobsfscan's semgrep rule is `languages: [java]` only — it cannot match the Kotlin idiomatic form, even though the protection is in place. |
| INFO | `android_prevent_screenshot` | ⏸ **Deferred (Day 30)** | Global `FLAG_SECURE` would block legitimate screenshots (X-rays, diagnosis sharing). Day 30 implements **per-screen** `FLAG_SECURE` on sensitive screens only. |
| INFO | `android_root_detection` | ⏸ **Deferred (Day 26)** | Needs new dependency + product decision (block / warn / log on rooted device). Day 26 — RASP. |
| INFO | `android_safetynet_api` | ⏸ **Deferred (Day 27)** | Needs Google Cloud project, server-side Play Integrity verification endpoint. Day 27. |

**Net result:** 8 → 7 findings. The single closed finding is the highest-priority WARNING (`allowBackup`); the remaining ERROR is a properly-documented false positive (taskAffinity mitigation in place); INFO items have specific roadmap-day owners.

### Hardening changes applied

[android/app/src/main/AndroidManifest.xml](android/app/src/main/AndroidManifest.xml):
- `android:allowBackup="false"` + `android:fullBackupContent="false"` — prevents `adb backup` and Google auto-backup of patient data
- `android:networkSecurityConfig="@xml/network_security_config"` — wires in the new HTTPS-only policy
- Manifest comment explaining why `singleTop` + `taskAffinity=""` is the correct StrandHogg 2.0 mitigation despite the SAST false positive

[android/app/src/main/res/xml/network_security_config.xml](android/app/src/main/res/xml/network_security_config.xml) (new):
- `<base-config cleartextTrafficPermitted="false">` — explicit HTTPS-only
- `<trust-anchors><certificates src="system"/></trust-anchors>` — release builds do **not** trust user-installed CAs
- `<debug-overrides>` — debug builds DO trust user CAs (allows mitmproxy / Burp during local pentest)

[android/app/src/main/kotlin/com/docdoc/app/MainActivity.kt](android/app/src/main/kotlin/com/docdoc/app/MainActivity.kt):
- `window.decorView.filterTouchesWhenObscured = true` in `onCreate` — drops touch events when another window obscures ours (tapjacking defence-in-depth)

### Semgrep — Generic SAST (`lib/`)

`semgrep --config p/default lib/` flagged **2 hardcoded API key matches** in
[lib/firebase_options.dart](lib/firebase_options.dart) (lines 53 and 61).

**Classification: false positive (low risk).**
Firebase `apiKey` values are public client identifiers by design, not secrets.
Google explicitly states they are safe to ship in client code. Firebase
security is enforced via **Firebase Security Rules** + **App Check**, not by
hiding the API key. See: https://firebase.google.com/docs/projects/api-keys

**Action item for later:** verify Firebase Security Rules and App Check are
properly configured (out of scope for Day 3 — tracked).

## SonarQube — Setup Pattern (Documentation)

SonarQube is a full code quality + security platform. Day 3 verified the
container starts; full project setup is interactive and is left as an
on-demand pattern.

### Start the server
```sh
docker run -d --name sonarqube -p 9000:9000 sonarqube:community
# Wait ~60s, then check: curl http://localhost:9000/api/system/status
# Web UI: http://localhost:9000  (default login: admin / admin → force-change)
```

### Scan the dental app (once project token is created in the UI)
```sh
# In project root, create sonar-project.properties:
cat > sonar-project.properties <<EOF
sonar.projectKey=dental_app
sonar.host.url=http://localhost:9000
sonar.login=<TOKEN_FROM_SONARQUBE_UI>
sonar.sources=lib,android/app/src/main,ios/Runner
sonar.exclusions=**/*.g.dart,**/build/**
EOF

sonar-scanner
```

**SonarQube vs Semgrep + mobsfscan:** SonarQube is a heavier all-in-one with
quality gates, tech debt scoring, and history. Semgrep + mobsfscan are
lighter, CI-friendly, and have stronger mobile-specific rule coverage.
For mobile work, **Semgrep + mobsfscan are the primary CI tools**;
SonarQube is for periodic deep audits.

## OPA — Policy-as-Code Smoke Test

```sh
echo '{"user": "alice", "role": "admin"}' | \
  opa eval -I -d <(echo 'package test; allow := input.role == "admin"') \
  'data.test.allow'
# → "result": [{"expressions": [{"value": true, ...}]}]
```

Used later for compliance gates (e.g., "no Activity may export without
permission" enforced at build time against the AndroidManifest).

## cosign — Supply Chain Signing

```sh
cosign generate-key-pair                 # creates cosign.key + cosign.pub
cosign sign --key cosign.key <artifact>  # signs an OCI artifact / file
cosign verify --key cosign.pub <artifact>
```

Used in Phase II / III for signing build artifacts (APKs, IPAs) and
verifying dependency provenance.

## Key Decisions

1. **OrbStack over Docker Desktop.** Docker Desktop's installer requires
   `sudo` for `cli-plugins` directory — unavailable in this session.
   OrbStack is a faster, Apple-Silicon-native, sudo-free alternative.

2. **mobsfscan via system pip, not pipx.** pipx build of mobsfscan fails on
   a Rust extension wheel. System pip3 has the pre-built wheel.

3. **Captured baseline, did not fix.** Per CLAUDE.md §4 Change Discipline,
   Day 3 only installs and audits. The 8 mobsfscan findings are tracked
   against future roadmap days that own each control.

4. **Firebase apiKey lint is a false positive.** Documented to prevent
   re-investigation later. The real security control is Firebase Security
   Rules — flagged for verification.

5. **Semgrep + mobsfscan as CI primary; SonarQube as on-demand audit.**
   The lighter SAST tools fit CI; SonarQube fits a quarterly deep audit.
