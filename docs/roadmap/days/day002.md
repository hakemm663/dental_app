## Installation Details

### Ghidra 12.1
```sh
brew install ghidra      # formula (not cask), installs OpenJDK 21 as dep
```
- GUI launcher: `/opt/homebrew/Cellar/ghidra/12.1/bin/ghidraRun`
- Headless analyzer: `/opt/homebrew/Cellar/ghidra/12.1/libexec/support/analyzeHeadless`
- Headless startup: ~900 ms

Headless analysis command pattern (used in CI/automation):
```sh
analyzeHeadless /tmp/project ProjectName \
  -import target.so \
  -postScript MyScript.java \
  -deleteProject
```

**SVD/GDT extensions** (peripheral definitions for embedded RE):
These are optional — install via Ghidra GUI → File → Install Extensions when
working on firmware or embedded targets. Not required for Android APK RE.

### IDA Free (manual — cannot automate)
IDA Free requires a free account registration at Hex-Rays before download.

```
https://hex-rays.com/ida-free/
```

Steps:
1. Register at Hex-Rays (email verification)
2. Download the macOS `.dmg` for IDA Free
3. Mount and drag to `/Applications`
4. License: free tier supports ARM64 and x86_64 analysis (no decompiler)
5. IDA Pro / IDA Professional adds Hex-Rays decompiler (paid)

For most roadmap days, Ghidra (free, with decompiler) covers what IDA Free would.

### r2frida
```sh
# r2pm was missing pkg-config — installed first
brew install pkg-config

r2pm -U                    # initialize/update package database
r2pm -ci r2frida           # clean install r2frida plugin
# Plugin installed to: ~/.local/share/radare2/plugins/io_frida.dylib
```

Usage — attach r2 to a live process on the emulator:
```sh
r2 frida://emulator-5554/com.docdoc.app
```
This combines static analysis power of r2 with Frida's live instrumentation.

### Blutter (Flutter AOT snapshot RE)
```sh
# macOS Sequoia deps
brew install cmake ninja capstone        # pkg-config already present
pip3 install pyelftools requests

# Clone
mkdir -p ~/tools
git clone --depth=1 https://github.com/worawit/blutter ~/tools/blutter
```

Usage (requires a **release** APK — `libapp.so` must exist):
```sh
# 1. Extract native libs from release APK
unzip app-release.apk 'lib/arm64-v8a/*' -d /tmp/dental_release_libs

# 2. Run Blutter — auto-detects Dart version, downloads Dart VM, compiles
python3 ~/tools/blutter/blutter.py \
  /tmp/dental_release_libs/lib/arm64-v8a \
  /tmp/blutter_out
```
Output: reconstructed Dart class names, method signatures, and symbol offsets
usable in Ghidra/r2 for annotating the release binary.

> **Debug APK note:** Debug Flutter builds use JIT — no `libapp.so` is produced.
> Blutter only works on release (AOT) builds. Use `flutter build apk --release`
> (requires signing config) or test on a third-party Flutter release APK.

### reFlutter
```sh
pipx install reflutter    # 0.8.6, Python 3.14.5
~/.local/bin/reflutter --help
```
reFlutter patches the Flutter engine to disable SSL pinning and expose the
snapshot hash, enabling man-in-the-middle attacks on apps with custom pinning.
Used in Days 8–9 (network security and SSL pinning bypass).

## Tool Test — Dental App APK

**Target:** `build/app/outputs/flutter-apk/app-debug.apk`
- Package: `com.docdoc.app`
- Size: 304 MB (includes Flutter engine + uncompressed native libs)
- DEX classes: 8268

### apktool — Resource Decoding
```sh
apktool d app-debug.apk -o /tmp/apktool_out -f
```
Result: decoded `AndroidManifest.xml`, resources, smali bytecode.

**Key permissions found:**
```xml
<uses-permission android:name="android.permission.INTERNET"/>
<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.RECORD_AUDIO"/>
```
(Full manifest audit deferred to a dedicated security assessment day.)

### jadx — DEX Decompilation
```sh
jadx -d /tmp/jadx_out app-debug.apk
```
Result: 8268 classes decompiled (45 non-fatal errors — normal for Flutter
debug APKs with mixed native + reflection-heavy Java). Output packages:
`android`, `androidx`, `com`, `firebase`, `_COROUTINE`.

### radare2 — Native Library Analysis
```sh
r2 -q -c "iI" lib/arm64-v8a/libflutter.so
```
```
arch     arm
bintype  elf
bits     64
machine  ARM aarch64
os       android
```
libflutter.so confirmed as 35 MB ELF arm64 Android binary. r2 analysis
is fast; full symbol resolution + ASLR-aware analysis used in later days.

### Ghidra Headless — Import Verification
```sh
analyzeHeadless /tmp/ghidra_test GhidraTest \
  -import lib/arm64-v8a/libflutter.so \
  -noanalysis -deleteProject
```
Result: `Headless startup complete (893 ms)` — import pipeline verified.
Full auto-analysis of libflutter.so takes ~5–10 min (skipped for Day 2;
done interactively in the GUI on demand).

### r2frida Plugin
```sh
r2 -q -c "L~frida" /dev/null
# io_frida.dylib loaded from ~/.local/share/radare2/plugins/
```
Live dynamic usage (requires booted emulator with frida-server running):
```sh
r2 frida://emulator-5554/com.docdoc.app   # attach to process
```

### Blutter
```sh
python3 ~/tools/blutter/blutter.py app-debug.apk/lib/arm64-v8a /tmp/blutter_out
# → Cannot find libapp file
```
Expected — debug APK has no `libapp.so`. Verified correct behavior.

## Key Decisions

1. **Ghidra over IDA Free as primary RE tool.** Ghidra has a full decompiler
   (free), strong ARM64 support, scriptable headless mode, and an active plugin
   ecosystem. IDA Free lacks a decompiler at the free tier. IDA Free installation
   documented but deferred to when disassembler-only analysis is preferred.

2. **Blutter over manual Dart snapshot RE.** Blutter automates Dart VM version
   detection and symbol recovery — manually reversing AOT Dart snapshots takes
   days. Blutter reduces this to minutes on release builds.

3. **reFlutter scope.** reFlutter modifies the Flutter engine — it's a
   destructive tool used only on pentest targets/test builds, never on
   production builds of the dental app.

4. **r2frida as the live bridge.** The combination of r2 (static analysis,
   scripting) + Frida (live memory, hooks) via r2frida covers what would
   otherwise require separate workflows in Ghidra + Frida independently.
