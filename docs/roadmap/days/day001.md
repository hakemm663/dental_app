### Objection (via pipx)
Roadmap listed npm; **Objection is a Python tool**, not an npm package.
`pipx` is used for clean isolated Python tool installs (no venv pollution).
```sh
brew install pipx
pipx ensurepath            # adds ~/.local/bin to PATH in shell profile
pipx install objection     # 1.12.4, Python 3.14.5
~/.local/bin/objection version   # objection: 1.12.4
```
> **PATH note:** Add `export PATH="$HOME/.local/bin:$PATH"` to `~/.zshrc` for
> global `objection` access without full path.

## Android Emulator — Rootable AVD Setup

### Why a separate AVD was needed

The existing AVD (`Pixel_10_Pro`) uses a **Play Store** system image
(`google_apis_playstore`). Play Store images block `adb root` and
`-writable-system` — both required for Frida and system CA cert install.

A second AVD (`pentest_pixel_36`) was created with a **Google APIs** (non-Play-
Store) image, which supports full root access.

```sh
# Install Google APIs arm64 system image (android-36.1)
sdkmanager "system-images;android-36.1;google_apis;arm64-v8a"

# Create rootable AVD
avdmanager create avd \
  -n pentest_pixel_36 \
  -k "system-images;android-36.1;google_apis;arm64-v8a" \
  -d pixel_6
```

**AVD inventory:**
| AVD | Image | Purpose |
|-----|-------|---------|
| `Pixel_10_Pro` | google_apis_playstore (API 37) | Normal app dev/debug |
| `pentest_pixel_36` | google_apis (API 36.1) | Pentest — rootable, Frida-ready |

### Boot command
```sh
$ANDROID_SDK/emulator/emulator \
  -avd pentest_pixel_36 \
  -writable-system \
  -no-snapshot \
  -no-boot-anim
```

**First-boot note:** The first cold boot of `pentest_pixel_36` takes 5–8 minutes
on Apple Silicon due to a known QEMU JIT `mprotect` warning in `-no-window`
mode. These are **non-fatal** — the emulator boots fully despite the log noise.
Subsequent boots are faster once a snapshot exists.

### Root + writable-system sequence (post-boot)
```sh
adb root                  # restart adbd as root
adb remount               # remount /system as read-write
adb shell whoami          # → root
```

## Burp Suite — Proxy + CA Certificate

### Proxy configuration
1. Launch Burp Suite → Proxy → Options → Add listener: `0.0.0.0:8080`
2. Configure emulator proxy: `adb shell settings put global http_proxy 10.0.2.2:8080`
   (`10.0.2.2` is the host machine from inside the Android emulator)

### Export Burp CA certificate
Burp generates its CA on first launch. Export it:
- Proxy → Options → CA Certificate → **Export certificate in DER format** →
  save as `burp_ca.der`

OR access `http://burpsuite` (or `http://10.0.2.2:8080`) from a browser while
Burp proxy is running and download the cert.

### Install as Android system CA (requires root + remount)
Android 7+ ignores user-installed CAs for app traffic by default; system CAs
are trusted unconditionally.

```sh
# Compute the OpenSSL hash filename Android uses for system CAs
CERT_HASH=$(openssl x509 -inform DER -subject_hash_old -in burp_ca.der | head -1)
openssl x509 -inform DER -in burp_ca.der -out "${CERT_HASH}.0"

# Push to system CA store
adb root && adb remount
adb push "${CERT_HASH}.0" /system/etc/security/cacerts/
adb shell chmod 644 /system/etc/security/cacerts/"${CERT_HASH}.0"
adb reboot   # required to reload CA store

# Verify (after reboot)
adb shell ls /system/etc/security/cacerts/ | grep "$CERT_HASH"
```

### mitmproxy CA (alternative / already generated)
mitmproxy's CA is pre-generated at `~/.mitmproxy/mitmproxy-ca-cert.pem`.
The identical push procedure applies — compute hash, push, reboot.

```sh
CERT_HASH=$(openssl x509 -subject_hash_old -in ~/.mitmproxy/mitmproxy-ca-cert.pem | head -1)
openssl x509 -in ~/.mitmproxy/mitmproxy-ca-cert.pem -out "${CERT_HASH}.0"
adb root && adb remount
adb push "${CERT_HASH}.0" /system/etc/security/cacerts/
adb shell chmod 644 /system/etc/security/cacerts/"${CERT_HASH}.0"
adb reboot
```

## Key Decisions

1. **Objection via pipx, not npm.** Roadmap listed npm but Objection is a Python
   package. pipx provides isolated installation without polluting the global pip.
2. **Separate pentest AVD.** Play Store AVDs can't be rooted; a dedicated
   `google_apis` AVD is required for Frida and system CA install. This is the
   correct production pentest setup.
3. **frida-server version must match frida host exactly.** 17.9.8 on both host
   and device — any mismatch causes connection failures.
4. **System CA over user CA for TLS interception.** Android 7+ apps with
   `cleartextTrafficPermitted=false` or `<network-security-config>` targeting
   only system CAs will reject user-installed certs. System CA install bypasses
   this for all apps, including the dental app under test.
